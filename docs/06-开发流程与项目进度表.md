# 接单智策开发流程与项目进度表

## 1. 文档用途

本文档是项目的执行看板，用来回答“现在做到哪里、下一步做什么、完成到什么程度才进入下一阶段”。每完成一个阶段，都要同步更新状态、验收结果和Git提交。

更新时间：2026-08-17

状态说明：

- ✅ 已完成：交付物存在并通过验收；
- 🟡 进行中：正在处理，尚未通过阶段验收；
- ⬜ 未开始：不得提前标记完成；
- 🔵 扩展项：不影响课程MVP提交。

## 2. 总体开发顺序

```text
需求与仓库基线
  -> 整理本地前后端骨架
  -> 先写评测案例与数据契约
  -> 后端Agent最小闭环
  -> 前端最小闭环
  -> 补齐核心Skills与报价Tool
  -> 状态保存与人工确认
  -> 测试、安全和真实用户验证
  -> 部署与课程提交材料
```

执行原则：先跑通一条从浏览器到数据库的完整链路，再横向增加Skill和页面；每个阶段必须有可验证结果，不能仅以“代码写完”作为完成标准。

## 8. 课程MVP最终完成标准

- [ ] 浏览器可完成“录入→Agent分析→补充信息→范围→工时→报价→人工确认”；
- [ ] 前端具有加载、空态、错误态和移动端布局；
- [ ] 后端具有API、数据库、Agent编排、Tool和规则降级；
- [ ] 至少4个核心Skill进入演示主流程，6个Skill均有明确契约；
- [ ] 报价金额只由确定性公式生成；
- [ ] Agent每个关键步骤可查看状态、耗时和结果摘要；
- [ ] 10个固定案例评测通过率不低于80%；
- [ ] 至少3名真实用户参与测试并记录反馈；
- [ ] 不提交API密钥、客户隐私、本地数据库或依赖目录；
- [ ] README、部署链接、PPT、海报、演示视频和开发证据齐全。
