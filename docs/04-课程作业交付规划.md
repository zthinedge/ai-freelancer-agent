# 课程作业交付规划

## 1. 最终提交目录建议

```text
群聊-小组编号-姓名-VibeCoding实践项目/
├─ 01-项目代码/
├─ 02-项目PPT/
├─ 03-项目海报/
├─ 04-项目说明文档/
├─ 05-演示视频/
├─ 06-Prompt与Bug记录/
└─ 07-用户测试证据/
```

## 2. 评分点映射

| 评分模块 | 本项目证据 |
|---|---|
| 项目前期准备 | 市场数据、目标用户、PRD、技术架构、验收指标 |
| Vibe Coding过程 | Prompt三轮迭代、AI代码提交记录、Bug修复前后截图 |
| 成果展示 | 新建项目、AI分析、报价、历史项目和移动端截图 |
| 方法论总结 | AI适合结构化提取但报价需本地校验；规则回退保障可用性 |
| 技术创新点 | 多步骤需求分析Agent + 结构化输出 + 可解释报价 |
| 扩展任务 | 3名真实用户测试，并完成一次反馈驱动迭代 |

## 3. 演示视频脚本（2-5分钟）

1. 0:00-0:25：说明自由职业接单中的需求模糊与报价痛点；
2. 0:25-0:55：展示用户画像和产品目标；
3. 0:55-1:45：输入模糊需求，生成澄清问题和范围拆分；
4. 1:45-2:25：展示任务工时、三级报价、风险与验收条件；
5. 2:25-2:50：展示历史项目和移动端适配；
6. 2:50-3:25：展示Prompt迭代、Bug修复和自动化测试；
7. 3:25-3:50：展示3名用户反馈及版本改进；
8. 3:50-4:00：总结AI Coding效率与局限。

## 4. 必须保留的过程证据

- 第一次生成项目骨架的Prompt与结果；
- 一次需求理解偏差及Prompt修正；
- 一次API或前端联调报错及完整错误信息；
- 一次AI生成测试后发现的真实Bug；
- 一次用户反馈驱动的界面或功能修改；
- 测试覆盖率、构建成功和线上访问截图。

## 5. 当前身份说明

若独立提交，在说明文档开头写明“独立完成”，无需虚构团队分工。若后续组队，再按照产品、开发、设计展示、文档和测试创新角色补充分工及可量化贡献。
